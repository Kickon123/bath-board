# 作業記録 2026-06-12 — 露天風呂「湯畑」温度モニター スマホ単体化＋クラウド配信

## ゴール
スマホで温度を取得 → クラウドサーバーへ送信 → 別モニターにURLでリアルタイム表示。
（従来はPC＋Androidエミュレータ(BlueStacks)＋ADBで取得していたのを、スマホ単体運用に移行）

## 結論（達成）
**スマホ1台だけで「取得→クラウド送信」が自走し、`https://bath-board.onrender.com` でどこからでも案内板を表示できる状態を実現。**

---

## 実施したこと

### 1. 温度取得方法の検討（エミュレータを使わない方法）
InkbirdはAPIを公開しておらず（公式が明言）、ゲートウェイ(IBS-M2)はWi-FiでInkbird/Tuyaクラウドに送信しているが、そこから取り出す正規手段が無い。検討した代替案:
- **Inkbird REST API**: `us.api-inkbird.com` を調査 → センサー温度は取得不可（dp_id=0に高湿度アラーム履歴のみ）。サブデバイス/現在値系エンドポイントは全て404。→ 不採用
- **Tuya Cloud API**: 認証は通るがデバイス一覧で permission deny。商用利用グレー＋トライアル期限の手動更新が必要。ユーザー意向で不採用
- **RTL-SDR + rtl_433（433MHz直接受信）**: アプリ・スマホ不要の唯一の方法だが、IBS-P02Rのデコード可否が未検証（ドングル必要）→ 保留
- **実機Android + Termux（採用）**: Inkbirdアプリ画面をADBで読み取る方式を、エミュレータでなく実機スマホ単体で動かす

### 2. 実機（Galaxy A20 / SC-02M, Android 9, 720x1560）セットアップ
- Termux(F-Droid版)導入、phone_setup.shでpython/adb/flask導入
- 各種権限付与、電池最適化除外、給電中スリープ無効、Wi-Fiスリープ無効
- 自己ADB接続（スマホが自分自身 127.0.0.1:5555 に接続）を確立

### 3. 取得ロジックをタブタップ方式に変更
Inkbirdデバイス画面の上部にある番号タブ(1,3,4,5,6)を1つずつタップして全5センサーを巡回。

### 4. クラウド中継サーバーを構築・デプロイ
- `cloud_server.py`（受信→保持→配信→案内板表示）
- GitHub(catrin48/bath-board) → Render無料Web Serviceにデプロイ
- URL: `https://bath-board.onrender.com`

### 5. スマホ→クラウド送信
- `adb_reader.py` に `push_to_cloud()` を追加。取得のたびにローカル/api/baths(完成形)をクラウドへPOST。

## 発生した問題と解決方法

| 問題 | 原因 | 解決方法 |
|---|---|---|
| エミュレータをやめたい | BlueStacks依存・PC常時必要 | 実機Android + Termuxで単体運用へ |
| 自己ADB接続が `unauthorized` のまま | 最初のUSBデバッグ許可で「常に許可」未チェック＝鍵が端末に保存されていない | 開発者オプション→「USBデバッグの許可を取り消す」→再接続時に「常に許可」付きで承認。PCの鍵をTermuxにコピー |
| 開発者オプションが開けない（adb intentをSamsungが拒否、TalkBack開発者設定と混同） | docomo/Samsung特有 | 設定→端末情報→ソフトウェア情報→ビルド番号7回タップで有効化、手動で開く |
| 1周で全5センサーが揃わない（スワイプ巡回が不安定） | 非力機でスワイプが効かず「前と同じ→終端」誤判定 | センサー切替を**タブタップ方式**に変更（スワイプ廃止） |
| 「湯畑が見つからない」→取得失敗 | `am start`方式では非力機で前面化が不安定、×ボタン誤爆でdocomoホームに脱出 | **クリーン起動方式**に変更（am force-stop→monkey起動→「湯畑」テキスト検索を6回リトライ→タップ）。app_launch_wait=9 |
| クラウドデプロイ失敗 `ModuleNotFoundError: No module named 'app'` | RenderのStart Commandが既定の `gunicorn app:app` | `gunicorn cloud_server:app` に修正 |
| 送信データが案内板に表示されない（baths=[]） | 生のtemperatures.json(IDキー辞書)を送っていた。案内板は baths配列形式を期待 | push_to_cloudでローカル `/api/baths`(完成形)を取得して転送する方式に変更 |
| USB接続中にrun.shが正常動作しない／頻繁に物理切断 | PCのadbとスマホ自己adbが同一adbd(127.0.0.1:5555)を競合。Type-C↔Type-Cも不安定。バッテリー100%で給電カット→切断 | **USBを抜くと自己接続のみで安定動作**。本番はUSB抜いて運用 |

## 最終構成

```
[スマホ Termux] 約4分ごと:
   adb_reader.py がInkbird画面をクリーン起動→タブ巡回で全5センサー取得
   → server.py /api/baths(完成形) → push_to_cloud でクラウドへPOST
        ↓ HTTPS
[クラウド Render] cloud_server.py
   /api/push で受信し latest.json 保持、/api/baths で配信、/ で案内板HTML配信
        ↓
[別モニター] https://bath-board.onrender.com/ を開くだけ（5秒ごとに自動更新）
```

### タイミング
- 取得→送信: 約4分おき（interval 180秒＋取得約60〜70秒）
- モニター画面更新: 5秒ごとにクラウドをポーリング（最大5秒遅れで反映）

### 主要ファイル
- `adb_reader.py` — 取得(タブ方式・クリーン起動)＋クラウド送信
- `server.py` — スマホ内ローカルFlask（/api/baths 完成形を作る）
- `config.phone.json` — 実機用設定（serial無し・自己接続、cloud.url/token、interval等）
- `cloud_server.py` — クラウド中継（deploy_cloud/ にデプロイ用一式）
- `static/base7-flat.html` — 案内板表示

## 運用上の注意
1. **本番はUSBを抜いて運用**（USB接続中は自己ADBと競合して不安定）
2. **スマホ再起動すると tcpip 5555 が消える** → 復活にPCを一度USB接続して `adb tcpip 5555` が必要（root無しAndroid9の制約）
3. **バッテリー保護(85%充電停止)をON**にして発火・劣化リスクを下げる。画面オフ・涼しい場所・不燃物の上に設置
4. Renderの無料枠は15分アクセスが無いと一時休止 → モニター常時表示なら休止しない
5. 取得スマホは消耗品扱い。クラウド側が独立しているので、スマホが壊れても表示インフラは無事

## 起動手順（USB不要・スマホTermuxで）
```
cp /sdcard/Download/bath_system/adb_reader.py ~/bath_system/adb_reader.py
cp /sdcard/Download/bath_system/config.phone.json ~/bath_system/config.json
bash ~/bath_system/run.sh
```
